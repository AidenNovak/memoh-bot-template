# 多轮实测与视频中的真实回复

2026-10-02在vultr-sg的独立Memoh实例测试了6个Bot、2个实际模型、每段同一会话连续8轮，共96条回复。称呼、物品、预算和目的地的更正，大部分都能接回来；角色口吻和行为边界仍有波动。为了制作可读的宣传片，补充一条普通聊天与工具使用的边界规则，再按相同输入复测4段、32条回复。两批结果分别公开，原始失败没有被后来的复测替换。

[两分钟宣传片](../promo/memoh-bot-template-multiturn-120s.mp4)主要展示四个Bot连续第4—7轮的16条真实回复节选，包含改口、换话题和回忆。影片不是整段实录：等待时间压缩，长回复只取连续原文片段，轮次不跳过。所有开场与完整八轮见下面的记录。

上游提交固定为`1bfb42154e09efacd34f68898ceaab78c10c85f3`。测试直接走Memoh原生WebSocket运行时，等待对应invocation进入completed，再读取持久化的用户与助手消息；每轮验证用户输入、对应turn_id、累计消息数，结束后再次回读所有八轮。没有把模板自带的示例对话当成模型回复。临时Bot截图后删除，四个已有演示Bot保留。

测试使用默认模板参数，没有人为设成“短回复”来让视频更好看。每个临时工作区限制0.5CPU / 512MiB / 5GiB，模型绑定沿用评估实例现有配置。原始批次的DeepSeek幽灵室友在聊天前遇到一次容器metrics HTTP500；仅补跑这组零回复的创建失败，错误保留在`setup_attempts`，没有丢弃或重抽任何已生成回复。

这次观察的是**当前上下文内的八轮连续性**。没有关闭会话再重开、没有强制上下文压缩，也没有测试长期记忆召回，因此不能据此推断跨会话记忆或数百轮稳定性。每个角色与模型只有一段输入序列，不是56个模板的质量排名。

### 工具标签问题与本次修订

原始批次中，DeepSeek芙莉莲第5轮与阿尼亚第8轮的持久化正文出现`DSML calls / invoke / parameter`标签，共2/48条；Kimi本批0/48条。这两条没有被剪成正常对白。该格式与[DeepSeek官方编码说明中的DSML工具调用结构](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/encoding/README.md)一致，但仅凭两条回复无法判定是模型、代理兼容层还是宿主提示的具体原因。

评估实例中DeepSeek模型的config为空，Kimi声明了reasoning和tool-call兼容性。宿主提示中仍有工作区与记忆说明，可能推动没有工具声明的模型输出工具样式文字，这是排查推测；本次没有改模型提供商配置。模板补充的规则是：

> 同一会话的称呼、物品、预算和更正直接利用当前上下文，后来的更正覆盖旧信息；已经用掉或移走的物品不重新出现。普通闲聊不主动查写工作区或长期记忆，用户明确要求跨会话留存、检索或现实操作时才按宿主规则使用工具。内部工具语法、调用标签和分析过程不能作为角色对白输出。

这条规则纳入56个模板的公共自然回应约定。复测不会证明工具标签问题已普遍修复；原始反例继续公开，视频来源校验会拒绝含工具标签的整轮回复，即使选中的小片段恰好没有标签。

## 修订后复测

四段复测都完成8轮，32条持久化正文均未出现DSML标签。芙莉莲是原来有标签泄露的同角色、同模型对照；阿尼亚本次使用Kimi，所以不能把它当作DeepSeek阿尼亚已经修复的证据。单次复测与随机生成不足以建立因果结论。

这四段的回复长度中位数分别为50.5、75.5、99、322.5字符。TRPG仍长，影片第4轮取库存状态、第7轮取库存清点的连续原文；其他节选尽量取回答开头。完整文本、物品数量的新设定和玩家动作都留在公开记录中。影片是有来源的样例展示，不宣称角色始终自然、指代永不出错或长期记忆可靠。


## 复现

先在自己的开发实例配置上述两个模型，使用服务端已有认证环境，按顺序运行：

```sh
# 新报告路径，避免覆盖已有试验；默认6个角色×2模型×8轮。
python3 scripts/evaluate_multiturn.py \
  --report /private/eval/new-multiturn.json \
  --registry /private/eval/capture.json --retain-capture

# 截图阶段读取完整会话，不发送新消息；需专用Chrome已登录该实例。
MEMOH_MULTITURN_REPORT=/private/eval/new-multiturn.json \
  node scripts/capture_multiturn_ui.mjs

# 截图结束仅删除登记的本次临时Bot。
python3 scripts/evaluate_multiturn.py --cleanup \
  --report /private/eval/new-multiturn.json --registry /private/eval/capture.json
```

脚本使用`MEMOH_URL`与`MEMOH_TOKEN`，或`MEMOH_USERNAME` / `MEMOH_PASSWORD`。`--pairs`可指定角色与模型组合；`--retry-empty-cases`只补零回复的HTTP500创建失败。请为每次试验使用新的报告和登记路径。截图脚本默认读取本库followup记录中四个Bot的临时名字，重做实验时用`MEMOH_MULTITURN_REPORT`指向新报告。
