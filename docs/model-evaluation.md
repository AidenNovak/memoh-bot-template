# 真实模型回答测试

2026-10-02追加了[六个Bot的八轮连续对话实测](multiturn-evaluation.md)，以及展示四个Bot连续第4—7轮真实回复的[两分钟影片](../promo/memoh-bot-template-multiturn-120s.mp4)。本页保留较早的90条对比，新旧试验单列。

2026-10-01，在独立的 Memoh 源码实例测试了 DeepSeek V4 Flash 和 Kimi K3。上游锁定 `1bfb42154e09efacd34f68898ceaab78c10c85f3`，每个场景创建临时 Bot，通过 Memoh 原生 WebSocket 发消息，再回读持久化聊天记录。没有绕过 Memoh 直接请求模型。

公开记录共 **90 条回答**，另有原生 Web UI 的实际聊天验证。覆盖重点是口吻是否自然、是否回应用户刚说的细节、能否少说流程、是否保留玩法的状态与玩家选择。没有为全部56个角色作质量评分。

## 根据回答继续调整

默认新增 `roleplay_intensity=1` 和 `conversation_style=自然聊天`。提示词先要求回应用户刚说的具体内容，日常交流尽量简短；角色工作流改成按需使用，用户要求认真分析时再展开。下调角色腔的示例和随口聊天示例也加入全部56个模板。

阿尼亚的初版容易变成成人辅导员，TRPG开场容易展示过多规则，所以进一步修改了这两类场景。另一起复测的猫猫与密室强化了已知线索、推测和玩家声明物品的边界。[四类场景12条复测](../verification/model-replies/refined-scenes.json)记录了所用参数和实际提示词 SHA-256。

角色强度0的第一次测试仍出现“人类的下午”这类角色口吻。只加一句降低强度不足以退出角色，因此渲染器现在在强度0或选择退出角色时移除身份、剧情、工作流和角色示例，改用普通助手提示词。[初次失败记录](../verification/model-replies/intensity-0-initial.json)与[修正后2条记录](../verification/model-replies/intensity-0.json)均保留；另有[强度3的2条记录](../verification/model-replies/intensity-3.json)。退出角色不代表固定短答，技术问题仍可能得到较长解释。

Kimi K3复测了马斯克、蒋介石、芙莉莲、阿尼亚、TRPG和幽灵室友，每个角色两轮，共[12条回答](../verification/model-replies/second-model.json)。日常角色没有固定套用汇报标题，TRPG仍倾向于更详细地叙述场景。

## 原生界面中的一段对话

在实际部署的Memoh Web中输入：“窗边那只杯子已经凉了。今天不想做任务，就陪我看一会儿雨吧。”芙莉莲模板曾回复：

> 嗯，那就坐着吧。
>
> 雨不急，我们也不急。你什么时候想说话都可以，不想说也行。

这是实际模型输出，宣传片使用了其中的原句；[素材来源记录](../promo/evidence.json)保留该次输出，后续新一轮界面验证与截图位于[验证记录](../verification/memoh-ui.json)和[聊天截图](../verification/memoh-chat.png)。

## 仍然存在的不足

- 阿尼亚有时仍使用较成熟的安慰措辞，角色辨识度会减弱。
- TRPG偶尔会在开场补充玩家的细小动作；用户自主选择的约束仍需模型遵守。
- 猫猫和密室有时把合理推测说得过于确定，需要继续加强事实与推测的区分。
- 强度旋钮是提示词控制，不是输出风格的确定性开关；同一模型不同轮次也会有波动。

可保留四个演示Bot继续体验，见[部署说明](deployment.md)。复测脚本 `scripts/evaluate_model_replies.py` 会创建、使用并删除自己的临时Bot，需预先配置可用聊天模型；不修改已有用户Bot。
